# Extraction of Handwritten Form Fields (OCR) for the Nepali Devanagari Script.

This is a complete pipeline that processes a completed Nepali membership form, matches it with a template, and retrieves 9 handwritten Devanagari text fields utilizing a CRNN model with CTC decoding and some NLP back-end refinement.

## Problem Statement

Nepal has a huge backlog of handwritten government documents — citizenship certificates, land registries, health records — that have never been digitised. Doing this by hand is slow and expensive, and people make mistakes typing it all in manually. OCR for printed text is a solved problem at this point, but handwritten Devanagari is a different story: the matras (the vowel marks that sit above, below, or beside a consonant) are hard for models to pick up reliably. This project tries to handle the whole thing end to end — you feed in a scanned form, you get structured data out.

## System Overview

The pipeline runs through 7 stages:

1. **Template rasterisation** — the blank form template gets converted from PDF to an image first, so there's something to align the actual scan against later.
2. **Load and deskew the scan** — the uploaded photo or scan of the filled form gets loaded in and straightened out.
3. **Alignment** — ORB feature matching and homography line the scan up with the reference template, correcting for rotation, skew, whatever angle it was photographed at.
4. **Crop the fields** — once aligned, the 9 field zones (name, address, etc.) get cropped out individually.
5. **Recognition** — each crop goes through the CRNN model, which spits out a raw text prediction.
6. **NLP post-processing** — Unicode normalisation plus vocabulary-based fuzzy matching cleans up whatever the model got slightly wrong.
7. **Output** — everything gets returned as a JSON dictionary.

## Model Description

The architecture relies on a CRNN, utilizing VGG16 as the feature extractor, succeeded by a 2-layer bidirectional LSTM for modeling sequences, and concluding with a CTC layer for decoding. Training occurred in two phases: initially on HindiSeg [22], comprising around 20,000 handwritten Hindi images from diverse sources, followed by training on handwritten Nepali data featuring different fonts generated by the computer. The vocabulary and trained weights are contained within the `.pth` checkpoint file.

## Results

- **Best validation word accuracy (synthetic Nepali font data):** 49.1% (epoch 19 checkpoint, used in the demo)
- **Best overall word accuracy:** 52.23% (Phase 2b checkpoint)
- **Live demo field accuracy on real handwritten forms:** roughly 78–89% for neat handwriting on common names — but this was only tested on 2 forms, so it's not a number you should generalise from.

Worth being upfront about this: the synthetic validation accuracy comes from font-rendered images, not actual handwriting. Real-world handwriting is messier, so performance there is likely lower than these numbers suggest.

## Limitations

- Trained on synthetic, font-rendered data, so there's a real domain gap when it hits actual handwriting
- ~49–52% word accuracy on synthetic validation isn't good enough for unassisted production use
- Matra recognition is where the model fails most often
- The NLP fuzzy-correction step only runs on last names and districts — it was excluded from first names because it kept over-correcting them
- No real handwritten test set was used for evaluation, so these numbers should be read with that caveat in mind
